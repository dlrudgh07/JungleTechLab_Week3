# 03. 사용 설명서

## 1. 요구 환경

| 항목 | 요구 사항 |
|---|---|
| OS | Windows 10 이상 (DirectX 11 지원) |
| IDE | Visual Studio 2022 이상 <br/>(솔루션은 VS18 형식, 플랫폼 도구 집합 `v145`로 저장되어 있음) |
| 워크로드 | "C++를 사용한 데스크톱 개발" |
| C++ 표준 | C++20 (`/std:c++20`) |
| 플랫폼 | **x64 권장** (Win32도 구성은 있으나 x64로 개발/검증됨) |
| SDK | Windows 10 SDK (`WindowsTargetPlatformVersion = 10.0`) |

> **VS 버전이 낮아 `v145` 도구 집합을 못 찾는다면**
> 프로젝트 우클릭 → 속성 → 일반 → 플랫폼 도구 집합을 설치된 버전(`v143` 등)으로 바꾸면 됩니다.
> 또는 솔루션을 열 때 뜨는 "프로젝트 대상 다시 지정" 대화상자에서 확인을 누르세요.

외부 라이브러리는 **별도 설치가 필요 없습니다.** ImGui와 JSON은 소스가 리포지토리에 포함되어 있고,
DirectX는 `#pragma comment(lib, ...)`로 링크됩니다.

```cpp
// Renderer.h
#pragma comment(lib, "user32")
#pragma comment(lib, "d3d11")
#pragma comment(lib, "d3dcompiler")
```

## 2. 빌드와 실행

```
1. JungleTechLab_Week3.sln 열기
2. 상단 구성: Debug / x64
3. 솔루션 탐색기에서 JungleTechLab_Week3 우클릭 → "시작 프로젝트로 설정"
4. F5 (디버깅 시작) 또는 Ctrl+F5
```

### ⚠️ 작업 디렉터리 주의

엔진은 씬 파일을 **실행 시 작업 디렉터리 기준 `.\Assets\`** 에서 찾습니다.

```cpp
// FileManager.h
inline constexpr std::string_view kDefaultRootPath   = ".\\";
inline constexpr std::string_view kDefaultAssetsPath = ".\\Assets\\";
```

Visual Studio에서 F5로 실행하면 작업 디렉터리가 **프로젝트 디렉터리**(`JungleTechLab_Week3\`)이므로
`JungleTechLab_Week3\Assets\SceneData\` 를 정상적으로 찾습니다.

하지만 빌드된 `.exe`를 탐색기에서 직접 더블클릭하면 작업 디렉터리가 `x64\Debug\`가 되어
**씬 로드가 실패합니다** (콘솔에 `Failed to load scene ...: file not found.` 로그가 뜹니다. 크래시는 나지 않습니다).

해결책 둘 중 하나:
- exe 옆에 `Assets` 폴더를 복사해 둔다
- 프로젝트 속성 → 디버깅 → 작업 디렉터리를 `$(ProjectDir)`로 지정한다 (F5 실행 시 기본값)

> 빌드 후 자동 복사(Post-Build Event)는 **아직 설정되어 있지 않습니다.** 추가하면 편해집니다.

### 실행 직후 상태

`FEngineLoop::Init`이 마지막에 `LoadScene("TestScene")`를 호출하므로,
큐브 두 개가 배치된 기본 씬이 뜹니다. 다른 씬으로 시작하고 싶으면 이 줄을 바꾸세요.

```cpp
// LaunchEngineLoop.cpp
mSceneManager->NewScene();
mSceneManager->LoadScene("TestScene", *mFileManager);   // ← 시작 씬
```

## 4. 조작법

### 카메라

| 입력 | 동작 |
|---|---|
| **마우스 우클릭 드래그** | 시점 회전 (Yaw / Pitch) |
| **W / S** | 앞 / 뒤 이동 |
| **A / D** | 좌 / 우 이동 |
| **E / Q** | 위 / 아래 이동 (월드 Z축) |
| **마우스 휠** (이동키를 누르지 않은 상태) | 줌 (원근일 땐 전진/후진, 직교일 땐 `mOrthoDistance` 조절) |
| **마우스 휠** (이동키를 누른 상태) | **카메라 이동 속도 조절** (0.1 ~ 100) |

- 키를 떼면 지수 감쇠로 부드럽게 멈춥니다 (`Damping = 6.0`)
- 마우스가 ImGui 창 위에 있을 때는 카메라가 반응하지 않습니다 (`io.WantCaptureMouse`)
- 카메라 위치/회전은 Control Panel에서 숫자로 직접 입력할 수도 있습니다

### 선택과 조작

| 입력 | 동작 |
|---|---|
| **좌클릭** (물체 위) | 액터 선택 → 주황색 외곽선 + 기즈모 표시 |
| **좌클릭** (빈 공간) | 선택 해제 |
| **좌클릭 드래그** (기즈모 축 위) | 해당 축으로 이동 / 회전 / 스케일 |
| **Space** | 기즈모 모드 순환 (Translate → Rotate → Scale) |

기즈모 축 색: **X = 빨강, Y = 초록, Z = 파랑** (월드 축 표시와 동일한 규칙)

### 기즈모 모드

| 모드 | 모양 | 동작 |
|---|---|---|
| **Translate** | 화살표 3개 | 축 방향으로 끌어 이동 |
| **Rotate** | 원(링) 3개 | 링을 따라 돌려 회전 (한 바퀴 이상 누적 가능) |
| **Scale** | 막대 + 큐브 핸들 | 끌어서 축별 크기 조절. 막대 끝까지 끌면 2배 |

모드는 Space 키, 또는 Control Panel의 `Gizmo Mode` 드롭다운 / `Next Gizmo Mode` 버튼으로 바꿉니다.

## 5. Control Panel 사용법

### Spawn Actor — 액터 만들기

1. `Primitive Type` 드롭다운에서 도형 선택 (Sphere / Cube / Triangle / GizmoArrow / Circle)
2. `Number of spawn`에 개수 입력 (최소 1)
3. `Spawn` 버튼

생성된 액터는 원점 `(0,0,0)`에 크기 1로 놓입니다. 여러 개를 한 번에 만들면 **같은 자리에 겹쳐서** 생기므로,
기즈모로 옮기거나 Property 창에서 좌표를 바꿔 주세요.

### Scene Control — 씬 저장 / 불러오기

| 버튼 | 동작 |
|---|---|
| `New scene` | 현재 월드를 지우고 빈 월드 생성. UUID 카운터도 0으로 초기화 |
| `Save scene` | `Assets\SceneData\<Scene Name>.Scene` 으로 저장 |
| `Load scene` | 같은 경로에서 불러오기 |

- `Scene Name`은 확장자 없이 입력합니다 (예: `MyScene` → `MyScene.Scene`)
- 같은 이름으로 저장하면 **덮어씁니다** (확인 대화상자 없음)
- 없는 이름을 불러오면 콘솔에 실패 로그만 남고 현재 씬이 유지됩니다
- 저장 시 기존 파일의 `Version` 값을 읽어 유지합니다

기본 제공 씬: `Default.Scene`, `TestScene.Scene`, `test1.Scene`

### Camera Control

| 항목 | 설명 |
|---|---|
| `Show Flags` → `Wire frame` | 와이어프레임 렌더링 토글 |
| `Show Flags` → `World axis` | 월드 축(빨강/초록/파랑 선) 표시 토글 |
| `Show Flags` → `Orthogonal` | **원근 ↔ 직교 투영 전환**. 1초 동안 부드럽게 보간됨 |
| `FOV` | 시야각 (0~180°) |
| `Location` / `Rotation` | 카메라 위치·회전 직접 입력 |

> 액터를 선택한 상태에서 직교로 전환하면, 그 액터까지의 깊이를 `mOrthoDistance`로 잡아
> 전환 후에도 대상이 화면에서 비슷한 크기로 남습니다.

### Memory Info

전역 `new` / `delete` 오버로드가 집계한 값입니다.

- `Total allocated memory count` : 현재 살아 있는 할당 개수
- `Total allocated memory size` : 현재 할당된 바이트 수

액터를 만들고 지웠을 때 숫자가 원래대로 돌아오는지 보면 누수를 눈으로 확인할 수 있습니다.

## 6. Property Window — 선택 액터 편집

액터를 선택하면 세 줄이 나타납니다. 드래그하거나 더블클릭 후 숫자를 입력합니다.

| 항목 | 값 | 비고 |
|---|---|---|
| `Translation` | X, Y, Z | 월드 위치 |
| `Rotation` | **Roll, Pitch, Yaw** 순서 | ⚠️ 씬 파일의 저장 순서(`[Pitch, Yaw, Roll]`)와 다릅니다 |
| `Scale` | X, Y, Z | 최솟값 `0.001` 로 강제 (`MIN_SCALE`) |

> **왜 스케일에 하한이 있나?**
> 스케일이 0이 되면 월드 행렬의 역행렬이 존재하지 않아 그 액터를 **클릭할 수 없게** 됩니다.
> 피킹이 `WorldTransformMatrix.Inverse()`에 의존하기 때문입니다. 그래서 0.001로 막아 뒀습니다.

편집은 액터의 **루트 컴포넌트**에 적용됩니다. 루트가 없으면 아무 일도 일어나지 않습니다.

## 7. Object List Panel — 전체 객체 목록

`GUObjectArray`에 등록된 **모든 `UObject`**를 UUID 순으로 보여 줍니다.
액터뿐 아니라 컴포넌트, `UWorld`까지 전부 나옵니다. 각 항목에 표시되는 것:

- `Class:` 런타임 클래스 이름 (`GetRuntimeClass()->Name`)
- `UUID:` 고유 번호
- `AActor` 파생인 경우에만 `Select` / `Delete` 버튼

현재 선택된 액터는 **연노랑 배경**으로 강조됩니다.

> 목록은 매 프레임 다시 만들지 않습니다. `GUObjectRevision`(객체 생성/소멸 시 증가)이 바뀐 프레임에만
> 새로 수집하고 정렬합니다. 객체가 많아져도 GUI가 느려지지 않게 하려는 최적화입니다.

`Delete`를 누르면 월드에서 제거하고 즉시 `delete` 합니다. 선택 중이던 액터라면 선택도 해제됩니다.

## 8. Console — 로그

코드 어디서든 두 매크로로 로그를 남길 수 있습니다.

```cpp
#include "Console.h"

UE_LOG("printf 스타일: %d, %s", 42, "hello");     // snprintf 기반
UE_LOG_F("std::format 스타일: {}, {}", 42, "hi"); // std::format 기반 (권장)
```

- 최대 줄 수를 넘으면 오래된 줄부터 버립니다
- 스크롤이 맨 아래에 있으면 자동으로 따라 내려갑니다
- 씬 로드 실패, 액터 선택 등 엔진 내부 이벤트도 여기에 찍힙니다

## 9. 단위 테스트 실행

`Test/UnitTest` 프로젝트가 googletest 기반 테스트를 담고 있습니다.

```
1. 상단 메뉴 → 테스트 → 테스트 탐색기
2. "모두 실행"
```

googletest는 **NuGet 패키지**로 관리됩니다 (`Test/UnitTest/packages.config`).
복원이 안 되면 솔루션 우클릭 → "NuGet 패키지 복원"을 실행하세요.

현재 테스트가 있는 영역:

| 파일 | 대상 |
|---|---|
| `TestsTArray.cpp` | `TArray` |
| `TestSparseArray.cpp` | `TSparseArray` (free-list 재사용, 인덱스 안정성) |
| `TestObject.cpp` | `UObject` — UUID, `IsA`, `Cast`, 직렬화 |
| `TestActor.cpp` | `AActor` — 컴포넌트 추가/제거, 직렬화 |
| `TestWorld.cpp` | `UWorld` — 액터 추가/제거, `Update` 호출, 직렬화 |
| `TestFileManager.cpp` | `FFileManager` — 읽기/쓰기, 경로 탈출 차단 |
| `TestSceneData.cpp` | `FSceneData` / `FPrimitiveData` JSON 변환 |

렌더링, 입력, 기즈모는 **테스트가 없습니다** (D3D 디바이스와 Win32 창이 필요하기 때문).

## 10. 자주 겪는 문제

| 증상 | 원인 / 해결 |
|---|---|
| 씬이 안 불러와지고 콘솔에 `file not found` | 작업 디렉터리 문제. 2절의 "작업 디렉터리 주의" 참고 |
| `v145 도구 집합을 찾을 수 없음` | 프로젝트 속성에서 설치된 도구 집합으로 변경 |
| 테스트 프로젝트 빌드 실패 (gtest 헤더 없음) | NuGet 패키지 복원 |
| 액터가 클릭이 안 됨 | 스케일이 너무 작지 않은지 확인 (`MIN_SCALE = 0.001`). 또는 기즈모에 가려진 상태일 수 있음 |
| Alt+Tab 후 카메라가 계속 움직임 | `WM_KILLFOCUS`에서 처리하도록 되어 있음. 재현되면 버그로 보고 |
| 창 크기 조절 중 화면이 멈춤 | 정상. `WM_ENTERSIZEMOVE`에서 16ms 타이머로 `Tick`을 계속 돌리도록 처리되어 있음 |
| FPS가 120에서 안 올라감 | 의도된 동작. `FFrameTimer(120)`이 목표 프레임 시간까지 대기 |
