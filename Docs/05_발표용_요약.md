## A. 10분 발표 대본

### 0분 — 한 문장으로 (30초)

> "저희 엔진은 **DirectX 11 위에서 도는 언리얼 스타일의 씬 에디터**입니다.
> 목표는 '게임을 만드는 것'이 아니라 '엔진이 매 프레임 무슨 일을 하는지 직접 만들어 보며 이해하는 것'이었고,
> 그래서 구조를 언리얼과 최대한 똑같이 맞췄습니다."

### 1분 — 데모 먼저 (2분)

말보다 화면이 빠릅니다. 이 순서로 보여 주세요.

1. **실행** → 기본 씬(큐브 두 개)이 떠 있는 상태
2. **카메라** 우클릭 드래그로 회전 + WASD 이동 → "키를 떼면 부드럽게 멈춥니다. 지수 감쇠를 씁니다."
3. **스폰** Control Panel에서 Sphere를 3개 스폰
4. **선택** 구를 클릭 → 주황 외곽선 + 기즈모 등장
   → "외곽선은 스텐실 버퍼로 그립니다. 물체가 멀어져도 **항상 3픽셀**로 보이게 계산합니다."
5. **기즈모** 드래그로 이동 → Space로 회전 모드 → 회전 → Space로 스케일 모드 → 크기 조절
6. **투영 전환** Show Flags → Orthogonal 체크
   → **"여기가 저희 엔진의 하이라이트입니다."** 1초 동안 원근에서 직교로 부드럽게 넘어감
   → 전환 도중에도 물체를 클릭해 보이기
7. **저장/로드** 씬 이름 입력 → Save → New scene(다 사라짐) → Load(복원)

### 3분 — 구조 설명 (3분)

칠판이나 슬라이드에 이 그림 하나면 충분합니다.

```
  [입력]            [게임]              [렌더]
WndProc          UWorld::Update      GraphicsManager
   ↓ 큐에 쌓기        ↓ 액터 순회          ↓
FInputState  →   TArray<FRenderInfo> → URenderer → GPU
                      ↑                   ↑
                 (오브젝트 계층은        (렌더 계층은
                  D3D를 모름)           액터를 모름)
```

**핵심 세 가지만 말합니다.**

1. **`FRenderInfo`가 두 세계를 잇는 유일한 접점입니다.**
   `{ 어떤 도형, 어떤 행렬, 누구인지(ID), 무슨 색 }` 이 네 개가 전부입니다.
   덕분에 게임 로직 쪽은 DirectX를 전혀 모르고, 렌더러는 액터를 전혀 모릅니다.

2. **객체는 포인터가 아니라 인덱스로 식별합니다.**
   모든 `UObject`는 생성자에서 전역 `TSparseArray`에 자기를 등록하고 `InternalIndex`를 받습니다.
   `TSparseArray`는 삭제해도 인덱스가 밀리지 않는 배열(free-list)이라,
   마우스로 클릭했을 때 인덱스 하나로 O(1) 역참조가 됩니다.

3. **리플렉션은 매크로 한 줄입니다.**
   `REFLECT_CLASS(AActor, UObject)` 하나가 클래스 이름 + 부모 + 생성자 람다를 만들어 주고,
   그걸로 `IsA` / `Cast` / **JSON에서 클래스 이름으로 객체 복원**이 전부 해결됩니다.

### 6분 — 우리가 가장 공들인 부분 (3분)

**통합 투영 행렬 (Unified Projection Matrix)**

> "보통 원근과 직교는 별개의 행렬입니다. 그러면 전환할 때 화면이 튀고,
> 더 큰 문제로 **그리는 행렬과 클릭 판정 행렬이 따로 놀아서 보이는 것과 클릭되는 게 어긋납니다.**
> 그래서 파라미터 `t` 하나로 둘을 연속적으로 잇는 행렬을 정의했습니다."

```
t = 1  →  원근 투영
t = 0  →  직교 투영
0<t<1  →  그 사이의 연속 상태
```

칠판에 쓸 두 줄:

```
result.M[2][3] = t / d;        // t=0이면 w가 상수 → 직교
result.M[3][3] = 1.0f - t;     // t=1이면 완전한 원근
```

> "그리고 **마우스 피킹은 이 행렬의 역행렬을 그대로 씁니다.**
> 그리는 수학과 클릭 판정 수학이 같은 식이라, 전환 중에도 보이는 대로 정확히 클릭됩니다.
> 체크박스를 누르면 `t`가 1초 동안 smoothstep으로 보간되고, 기즈모 크기와 외곽선 두께도
> 같은 `t`로 섞이기 때문에 전환 중 어색한 순간이 없습니다."

### 9분 — 지금 없는 것, 그래서 할 수 있는 것 (1분)

정직하게 말하는 편이 협업에 좋습니다.

- **없는 것**: 물리, 라이팅/텍스처, 메시 로딩(정점이 헤더에 하드코딩), 컴포넌트 부모-자식 계층, 멀티스레딩

- **그래서**: "**뼈대는 다 있고 살을 붙일 자리가 비어 있는 상태**입니다.
  `Tick()`에 `//Physics Threads` 주석 블록이 비어 있는데, 여기가 바로 다음 팀이 채울 자리입니다."

## B. 예상 질문과 답변

### 구조에 대한 질문

**Q. 왜 언리얼 구조를 그대로 따라 했나요? 그냥 베낀 것 아닌가요?**
> 구현은 전부 직접 했고, **차용한 것은 이름과 계층 구조**입니다.
> 이유는 두 가지입니다. 첫째, 검증된 설계를 따라가면 "왜 이 클래스가 필요한가"를 스스로 답해 볼 수 있습니다.
> 둘째, 팀원 대부분이 이후 언리얼을 다루게 되므로 개념 전이가 바로 됩니다.
> 실제로 `UObject` / `AActor` / `UActorComponent`의 역할 분리는 만들어 보기 전에는 잘 와닿지 않는 부분이었습니다.

**Q. STL을 감싼 `TArray`는 그냥 오버헤드 아닌가요?**
> 인라인 래퍼라 릴리스 빌드에서는 오버헤드가 사실상 없습니다.
> 목적은 성능이 아니라 **인터페이스 소유권**입니다. 사용처가 `std::vector`가 아닌 `TArray`에 의존하므로,
> 나중에 커스텀 얼로케이터나 자체 구현으로 내부를 바꿔도 호출부를 고칠 필요가 없습니다.
> 실제로 `TSparseArray`는 STL에 대응물이 없어 처음부터 직접 구현했습니다.

**Q. `TSparseArray`는 왜 필요했나요? `TArray`로 안 되나요?**
> `TArray`는 원소를 지우면 뒤가 앞으로 당겨집니다. 그러면 저장해 둔 인덱스가 전부 무효가 됩니다.
> 저희는 렌더 정보에 포인터 대신 인덱스를 담아 GPU 쪽으로 보내고, 클릭 시 그 인덱스로 객체를 되찾습니다.
> 그래서 **삭제해도 다른 원소의 인덱스가 변하지 않는 배열**이 필요했고,
> 빈 슬롯을 `union`으로 free-list로 엮어 재사용하는 구조로 만들었습니다.
> 언리얼의 `GUObjectArray`도 같은 이유로 sparse array입니다.

**Q. GC가 없는데 메모리 관리는 어떻게 하나요?**
> **소유권이 트리 구조를 따릅니다.** `UWorld` 소멸자가 액터를 `delete`하고, `AActor` 소멸자가 컴포넌트를 `delete`합니다.
> `UObject` 소멸자가 전역 배열에서 자기를 제거하므로 목록도 자동으로 정리됩니다.
> 추가로 전역 `new`/`delete`를 오버로드해 할당 개수와 바이트를 세고, 그 값을 에디터 UI에 실시간으로 띄웁니다.
> 액터를 만들었다 지웠을 때 숫자가 제자리로 돌아오는지 눈으로 확인할 수 있습니다.
> 다만 `delete` 전에 `World::RemoveActor`를 먼저 불러야 하는 순서 의존성은 남아 있습니다.

### 기능에 대한 질문

**Q. 마우스 피킹은 어떻게 구현했나요?**
> 네 단계입니다.
> ① 마우스 픽셀 좌표를 NDC로, ② **통합 투영 행렬의 역행렬**과 뷰 역행렬로 월드 공간의 Near/Far 두 점을 구하고,
> ③ 각 액터의 월드 행렬의 **역행렬로 광선을 로컬 공간에 끌고 들어간 뒤** Möller–Trumbore로 삼각형과 교차 판정,
> ④ 가장 가까운 것의 `InternalIndex`로 객체를 역참조합니다.
> ③에서 메시를 월드로 옮기지 않고 광선을 로컬로 가져오는 게 포인트입니다. 정점이 수천 개여도 역변환은 두 점에만 하면 됩니다.

**Q. 기즈모 드래그가 튀거나 발산하지 않던데, 어떻게 했나요?**
> 기즈모는 액터를 따라 움직입니다. 그래서 기준선을 매 프레임 갱신하면
> **결과가 다시 기준을 움직여서 발산합니다.**
> `BeginDrag` 시점에 축의 원점, 처음 잡은 지점, 그때의 막대 길이를 전부 고정해 두고,
> 이후 모든 계산을 그 기준에 대한 **상대량**으로 합니다.
> 회전은 추가로 ±180°를 넘어갈 때 직전 프레임 각도와 이어 붙여 누적각을 만듭니다.
> 그리고 드래그 중에는 히트 판정을 아예 건너뜁니다. 빠르게 끌면 커서가 축을 벗어나 드래그가 끊기기 때문입니다.

**Q. 선택 외곽선은 어떻게 그리나요?**
> 스텐실 버퍼 3패스입니다. ① 색 쓰기를 끈 채 원본 메시를 그려 스텐실에 1을 찍고,
> ② 살짝 키운 메시를 단색으로 그리되 **스텐실이 1이 아닌 곳만** 통과시켜 테두리만 남깁니다. ③ 상태 복구.
> 키우는 배율은 화면상 두께가 3픽셀이 되도록 카메라 깊이로부터 역산합니다.
> 깊이 d에서 화면이 담는 월드 높이가 `2·d·tan(fov/2)`이니, 이걸 픽셀 수로 나누면 픽셀당 월드 크기가 나옵니다.

**Q. 왜 기즈모는 물체에 안 가려지나요?**
> 기즈모를 그리기 직전에 **깊이 버퍼를 지웁니다**(`RenderOverlay` → `ClearDepth`).
> 물체 안에 파묻힌 액터도 기즈모는 잡을 수 있어야 하기 때문입니다.
> 반대로 월드 축은 깊이 버퍼를 유지한 채 그려서 물체 뒤로 자연스럽게 숨습니다.

**Q. 입력 처리에서 특별히 신경 쓴 부분이 있나요?**
> **`WndProc`에서는 아무것도 해석하지 않는다**는 원칙입니다.
> `WndProc`은 OS가 임의 타이밍에 몇 번이든 부르기 때문에, 거기서 상태를 바꾸면
> "한 프레임 안에 눌렸다 떼진" 입력이 유실되거나 중복 처리됩니다.
> 그래서 메시지를 큐에 쌓기만 하고, **프레임당 정확히 한 번** 해석해서
> `IsDown` / `WasPressed` / `WasReleased` 세 상태로 정리합니다.
> 추가로 OS 키 자동 반복은 `lParam` 30번 비트로 걸러내고, 포커스를 잃으면 눌린 키를 전부 해제합니다.

### 협업에 대한 질문

**Q. 이 엔진 위에 기능을 얹으려면 어디부터 봐야 하나요?**
> `LaunchEngineLoop.cpp`의 `FEngineLoop::Tick()` 하나만 읽으면 전체 흐름이 보입니다. 40줄쯤 됩니다.
> 그다음 관심 영역에 따라 `SceneManager`(에디터 UI/씬), `FEditorViewportClient`(입력/피킹),
> `GraphicsManager`(렌더 정책)로 내려가면 됩니다.
> 새 클래스나 도형을 추가하는 구체적 절차는 `Docs/04_확장_가이드.md`에 체크리스트로 정리해 뒀습니다.

**Q. 새 클래스를 추가할 때 주의할 점은?**
> 세 가지입니다.
> ① `REFLECT_CLASS` 매크로를 빠뜨리지 말 것,
> ② `new`가 아니라 `FObjectFactory::ConstructObject<T>()`로 만들 것 (안 그러면 런타임 타입 정보가 비어 크래시),
> ③ **`ObjectFactory.cpp`의 이름→클래스 테이블에 등록할 것.**
> ③을 빠뜨리면 저장은 되는데 로드할 때 예외가 납니다. 자동 등록은 아직 TODO로 남아 있습니다.

**Q. 테스트는 있나요?**
> googletest 기반 단위 테스트가 있습니다. 컨테이너(`TArray`, `TSparseArray`),
> 오브젝트 시스템(UUID / `IsA` / `Cast` / 직렬화), 액터·월드, 파일 매니저, 씬 데이터를 덮습니다.
> 반대로 렌더링·입력·기즈모는 D3D 디바이스와 창이 필요해 테스트가 없습니다. 이 부분은 눈으로 검증했습니다.

**Q. 알려진 문제나 한계는요?**
> 세 가지를 미리 말씀드립니다.
> ① **레이캐스트가 직전 프레임의 렌더 정보를 읽습니다** — 호출 순서 때문에 1프레임 지연이 있습니다. 순서를 바꾸면 해결됩니다.
> ② **컴포넌트 부모-자식 계층이 없습니다** — 액터가 루트 컴포넌트와 평평한 배열만 가져서, 사실상 모든 트랜스폼이 월드 좌표입니다.
> ③ **클래스 등록이 수동입니다.**
> 셋 다 코드에 `// Todo:` 로 표시해 뒀고, 확장 가이드 마지막 절에 우선순위와 손댈 파일을 정리했습니다.

## C. 한 장 요약 (슬라이드용)

```
JungleTechLab Engine — DirectX 11 미니 에디터 엔진

■ 무엇        언리얼 구조(UObject/Actor/Component/World)를 직접 구현한 3D 씬 에디터
■ 규모        엔진 코드 약 11,000줄 (외부 라이브러리 제외) · C++20 · 외부 의존성 4개

■ 핵심 설계 5
  1) 언리얼 구조 차용        — 개념 학습 + 이후 전이
  2) STL을 감싼 자체 컨테이너 — 인터페이스 소유권 확보
  3) 인덱스 기반 객체 식별    — TSparseArray + GUObjectArray
  4) 매크로 한 줄 리플렉션     — REFLECT_CLASS → IsA / Cast / JSON 복원
  5) 렌더와 피킹이 같은 수학   — 통합 투영 행렬과 그 역행렬

■ 되는 것     스폰 · 피킹 · 기즈모(이동/회전/스케일) · 씬 저장·로드(JSON)
              원근↔직교 부드러운 전환 · 스텐실 외곽선 · 와이어프레임 · 콘솔 · 단위 테스트
■ 안 되는 것   물리 · 라이팅/텍스처 · 메시 로딩 · 컴포넌트 계층 · 멀티스레딩
              → 뼈대는 완성, 살 붙일 자리가 비어 있음
```
