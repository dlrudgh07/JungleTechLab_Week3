# 04. 확장 가이드

이 엔진 위에 기능을 얹을 때 **어디를 건드려야 하는지** 정리한 문서입니다.
아직 자동 등록(리플렉션 코드 생성)이 없어서 손으로 손봐야 하는 지점이 몇 군데 있습니다.
빠뜨리면 컴파일은 되는데 런타임에 조용히 실패하므로, 체크리스트로 쓰세요.

## 1. 새 프리미티브(도형) 추가하기

예: 원뿔(Cone)을 추가한다고 가정합니다. **6곳**을 고쳐야 합니다.

### ① 열거형에 추가 — `enum.h`

```cpp
enum class EPrimitive
{
    EP_Sphere,
    EP_Cube,
    EP_Triangle,
    EP_GizmoArrow,
    EP_Circle,
    EP_Cone,      // ← 추가 (반드시 맨 뒤에)
```

> ⚠️ **중간에 끼워 넣지 마세요.** GUI 드롭다운(`primitiveTypeNames`)이 enum 값을 인덱스로 쓰기 때문에
> 순서가 어긋나면 "Sphere를 골랐는데 Cube가 나오는" 현상이 생깁니다.

### ② 정점 배열 헤더 만들기 — `Cone.h`

기존 `Cube.h`를 그대로 흉내 내면 됩니다. 삼각형 리스트(정점 3개 = 삼각형 1개)여야 합니다.

```cpp

FVertexSimple Cone_vertices[] =
{
    // x, y, z,   r, g, b, a
    { 0.0f, 0.0f, 1.0f,   1,0,0,1 },
    // ...

```

### ③ GPU 버퍼 생성 — `LaunchEngineLoop.cpp` (`FEngineLoop::Init`)

```cpp
mGraphicsManager->CreateBuffer(EPrimitive::EP_Cone, Cone_vertices, sizeof(Cone_vertices));
```

> `sizeof(배열)`을 넘겨야 합니다. 포인터로 넘기면 크기 정보가 사라집니다.

### ④ 직렬화 문자열 매핑 — `JsonUtil.cpp`

`EPrimitiveToJson`과 `EPrimitiveFromJson` **양쪽 모두**에 case를 추가합니다.
빠뜨리면 저장 또는 로드 시 `std::runtime_error`가 납니다.

```cpp

// ...

```

### ⑤ GUI 드롭다운 이름 — `SceneManager.cpp` (`updateControlPanelGUI`)

### ⑥ 피킹용 메시 등록 — `FEditorViewportClient.cpp` (`GetPrimitiveMesh`)

**이걸 빠뜨리면 화면에는 보이는데 클릭이 안 됩니다.** 가장 흔한 실수입니다.

```cpp
case EPrimitive::EP_Cone:
```

## 2. 새 컴포넌트 클래스 추가하기

예: `UConeComponent`

### ① 헤더 — `ConeComponent.h`

```cpp
#pragma once
#include "PrimitiveComponent.h"

class UConeComponent : public UPrimitiveComponent
{
    REFLECT_CLASS(UConeComponent, UPrimitiveComponent)   // ← 필수
public:
    UConeComponent();
    virtual ~UConeComponent();

    void Initialize();
    void Initialize(FVector location, FRotator rotation, FVector scale3D);
};
```

**규칙**
- `REFLECT_CLASS(자기이름, 부모이름)`을 클래스 본문 맨 위에 씁니다. (이 매크로는 끝에 `private:`을 남기므로 뒤에 `public:`을 다시 써야 합니다.)
- 기본 생성자가 반드시 있어야 합니다. 매크로가 만드는 팩토리 람다가 `new UConeComponent()`를 호출합니다.
- 초기화는 생성자가 아니라 **`Initialize()`** 에서 합니다.

### ② 구현 — `ConeComponent.cpp`

```cpp
#include "ConeComponent.h"

UConeComponent::UConeComponent() {}
UConeComponent::~UConeComponent() {}

void UConeComponent::Initialize()
{
    Initialize(FVector(0.f), FRotator(0.f, 0.f, 0.f), FVector(1.f));
}

void UConeComponent::Initialize(FVector location, FRotator rotation, FVector scale3D)
{
    UPrimitiveComponent::Initialize(EPrimitive::EP_Cone, location, rotation, scale3D);
}
```

### ③ 클래스 등록 — `ObjectFactory.cpp` ⚠️ 필수

**이걸 빠뜨리면 저장은 되는데 로드가 안 됩니다** (`Unknown class name: UConeComponent` 예외).

```cpp
TMap<FString, std::function<const FClassInfo* ()>> FObjectFactory::mClassInfoMap = {
    {"UObject",             &UObject::GetClass },
    {"AActor",              &AActor::GetClass },
    {"UActorComponent",     &UActorComponent::GetClass },
    {"USceneComponent",     &USceneComponent::GetClass },
    {"UPrimitiveComponent", &UPrimitiveComponent::GetClass },
    {"UCubeComponent",      &UCubeComponent::GetClass },
    {"USphereComponent",    &USphereComponent::GetClass },
    {"UWorld",              &UWorld::GetClass },
    {"UConeComponent",      &UConeComponent::GetClass },   // ← 추가
};
```

> 문자열은 `REFLECT_CLASS`에 넘긴 이름(`#className`)과 **정확히 같아야** 합니다.
> 테스트 코드처럼 런타임에 등록하려면 `FObjectFactory::RegisterClassInfo("이름", UConeComponent::GetClass())`를 쓰면 됩니다.

### ④ 프로젝트에 파일 추가

Visual Studio에서 "기존 항목 추가"로 넣으면 `.vcxproj`가 자동으로 갱신됩니다.
직접 만든 파일을 리포지토리에 추가만 하고 프로젝트에 넣지 않으면 컴파일되지 않습니다.

**체크리스트**

- [ ] `REFLECT_CLASS` 선언
- [ ] 기본 생성자 존재
- [ ] `Initialize()` 오버로드 (생성자가 아님)
- [ ] `ObjectFactory.cpp`의 `mClassInfoMap` 등록
- [ ] `.vcxproj`에 파일 추가

## 3. 새 액터 클래스 추가하기

컴포넌트와 절차가 같습니다. 다만 `AActor`는 `Update`를 오버라이드할 수 있습니다.

```cpp
class ARotatingActor : public AActor
{
    REFLECT_CLASS(ARotatingActor, AActor)
public:
    ARotatingActor() = default;

    virtual void Update(TArray<FRenderInfo>* outRenderInfos) override
    {
        // 자기 로직을 먼저 돌리고
        FRotator r = GetTransform().Rotation;
        r.Yaw += 1.0f;
        SetRotation(r);

        // 부모를 호출해 컴포넌트들의 렌더 정보를 수집해야 화면에 나온다
        AActor::Update(outRenderInfos);
    }
};
```

> ⚠️ `AActor::Update`를 호출하지 않으면 **아무것도 그려지지 않습니다.**
> `Update`가 "게임 로직"이자 "렌더 정보 수집"을 겸하고 있기 때문입니다.

`Update`에는 델타 타임이 전달되지 않습니다. 시간 기반 로직이 필요하면
`AActor::Update(float deltaTime, TArray<FRenderInfo>*)` 형태로 시그니처를 넓히고
`UWorld::Update`, `FSceneManager::Update`까지 함께 고쳐야 합니다. (이 엔진의 자연스러운 확장 지점 중 하나입니다.)

## 4. 직렬화할 필드 추가하기

새 멤버를 씬 파일에 저장하려면 두 함수를 **쌍으로** 오버라이드합니다.

```cpp
void UConeComponent::SerializeClass(json::JSON& outJson) const
{
    UPrimitiveComponent::SerializeClass(outJson);        // ① 부모 먼저
    outJson["Properties"]["mHeight"] = mHeight;          // ② 내 필드
}

void UConeComponent::DeserializeClass(const json::JSON& inJson)
{
    UPrimitiveComponent::DeserializeClass(inJson);       // ① 부모 먼저

    const json::JSON& propertiesJson = inJson.at("Properties");

    // ② 반드시 검증 후 읽기 — 이 엔진의 관례
    if (!propertiesJson.hasKey("mHeight")
        || propertiesJson.at("mHeight").JSONType() != json::JSON::Class::Floating)
    {
        throw std::runtime_error(std::format("{}: mHeight requires a float",
                                             GetRuntimeClass()->Name));
    }
    mHeight = propertiesJson.at("mHeight").ToFloat();
}
```

**관례 세 가지**
1. 부모 구현을 **먼저** 호출한다
2. 모든 필드는 `hasKey` + `JSONType()` 검사 후 읽는다 (배열이면 `length()`까지)
3. 실패는 `std::runtime_error`로 던지고, 메시지에 클래스 이름을 넣는다

`FVector` / `FRotator` / `EPrimitive`는 `JsonUtil.h`의 헬퍼를 쓰세요.

> **호환성 주의**: 기존 씬 파일에는 새 필드가 없으므로, 위 코드는 예전 씬을 로드할 때 예외를 던집니다.
> 구버전 호환이 필요하면 `hasKey`가 false일 때 기본값을 넣도록 하고,
> `Version` 필드(이미 파일 포맷에 있습니다)를 활용하세요.

## 5. GUI 패널 추가하기

`FSceneManager::UpdateGUI`가 ImGui 프레임의 시작과 끝을 관리합니다.

```cpp
void FSceneManager::UpdateGUI(const FGuiReference& guiReference)
{
    ImGui_ImplDX11_NewFrame();
    ImGui_ImplWin32_NewFrame();
    ImGui::NewFrame();

    updateControlPanelGUI(guiReference);
    updatePropertyWindowGUI(guiReference);
    updateObjectListPanelGUI(guiReference);
    // ← 여기에 내 패널 추가

    ConsoleWindow::GetInstance().Draw(mPanelWidth);
}
```

- `ImGui::Render()` 호출은 `FEngineLoop::Tick`의 렌더 블록에 있습니다. 패널 함수에서 부르면 안 됩니다.
- 패널이 필요한 엔진 객체는 `FGuiReference` 구조체를 통해 전달됩니다.
  (FrameTimer, GraphicsManager, ViewportClient, FileManager) 더 필요하면 이 구조체에 필드를 추가하세요.
- 세로 배치는 비율 상수로 관리됩니다: 컨트롤 40%, 프로퍼티 30%, 오브젝트 목록 나머지, 콘솔 30%.

## 7. 흔한 함정 모음

| 함정 | 증상 | 해결 |
|---|---|---|
| `new UMyComponent()` 직접 호출 | `mClassInfo`가 null → `GetRuntimeClass()` 크래시, `IsA` 실패 | 반드시 `FObjectFactory::ConstructObject<T>(...)` 사용 |
| `Initialize()` 호출 누락 | UUID가 쓰레기 값 → 목록/직렬화 이상 | 팩토리를 쓰면 자동 |
| `mClassInfoMap` 등록 누락 | 저장은 되는데 로드 시 `Unknown class name` | `ObjectFactory.cpp` 확인 |
| `GetPrimitiveMesh` 누락 | 보이는데 클릭이 안 됨 | `FEditorViewportClient.cpp` 확인 |
| `AActor::Update` 미호출 | 액터가 안 그려짐 | 오버라이드 끝에서 부모 호출 |
| 컴포넌트를 두 액터에 추가 | `SetOwner`의 `assert(mOwner == nullptr)` 실패 | 컴포넌트는 액터 하나에만 |
| 액터를 `delete` 하고 월드에서 안 지움 | 댕글링 포인터 → 크래시 | `World::RemoveActor(UUID)` 먼저, 그 다음 `delete` |
| 스케일 0 설정 | 클릭 불가 | `MIN_SCALE`로 막혀 있으나 코드로 직접 넣을 때 주의 |

## 8. 구조적으로 손보면 좋을 지점 (Week3 후보)

우선순위 순으로, **왜 그 자리인지**까지 적었습니다.

1. **컴포넌트 어태치 계층** — 현재 `AActor`는 `mRootComponent` + 평평한 배열만 가집니다.
   `USceneComponent`에 `mParent` / `mChildren`을 넣고 `GetWorldTransform()`이 부모를 거슬러 올라가 합성하면
   진짜 씬 그래프가 됩니다. 손댈 곳: `SceneComponent`, `Actor::GetTransform`, 직렬화(부모 UUID 저장).
2. **클래스 자동 등록** — `mClassInfoMap` 수동 등록을 없애기.
   `REFLECT_CLASS` 매크로 안에 정적 초기화 트릭(전역 객체 생성자에서 `RegisterClassInfo` 호출)을 넣으면 됩니다.
   코드에도 `// TODO: Automate the registration of class info` 로 남아 있습니다.
3. **레이캐스트 1프레임 지연 제거** — `FEngineLoop::Tick`에서 `SceneManager->Update()`를
   `ViewportClient->Update()`보다 먼저 부르도록 순서를 바꾸는 것으로 시작할 수 있습니다.
4. **액터 Tick에 델타 타임 전달** — 게임 로직을 넣으려면 필수.
5. **머티리얼 / 라이팅** — 현재 셰이더는 정점 색 + Tint뿐. 노멀을 정점 포맷에 추가하는 것이 첫걸음
   (`FVertexSimple`, 입력 레이아웃, `ShaderW0.hlsl`을 함께 수정).
6. **메시 파일 로딩** — 정점 배열 헤더(`Sphere.h` 2400줄)를 OBJ 로더로 대체.
7. **인덱스 버퍼** — 정점 중복 제거. 6번과 함께 하면 자연스럽습니다.
8. **Undo / Redo** — `TQueue`가 이미 있고 트랜스폼 변경 지점이 `FSceneManager` / `FGizmo`로 좁아서 붙이기 쉽습니다.
9. **빌드 후 Assets 자동 복사** — Post-Build Event 한 줄. 실행 편의성이 크게 올라갑니다.
10. **실제 스레드 분리** — `Tick()`의 네 블록 주석이 이미 경계를 그어 두었습니다.
